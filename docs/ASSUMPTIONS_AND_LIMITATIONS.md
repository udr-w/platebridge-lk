# Assumptions and limitations

- All people, organisations, incidents and locations are fictional demo entities.
- The active matching demonstration focuses on Galle; other districts show future network breadth.
- One “portion” is donor-described and not nutritionally standardised.
- Straight-line distance is adequate for sorting a demo and is not road travel time.
- Donors answer handling questions accurately; the prototype performs no physical inspection.
- Rule values illustrate workflow and have no official approval.
- The shared password and bearer token are deliberately demo-only. There is no password hashing, refresh token, rate limiting or robust session revocation.
- SQLite supports a local demonstration, not multi-region production concurrency.
- In-app messages/notifications refresh normally; no sockets, email, SMS or push are sent.
- PWA scope is installability and a stable shell; mutations are not queued offline.
- Environmental figures are avoided; displayed impact is activity-derived portions/rescues.
- Sinhala and Tamil copy is useful for a demonstration but needs native-speaker review.
- Windows launch files are provided; final assurance requires running them on Windows.
- The July 2026 npm advisory database flags development-tool transitive packages and React Router's server-component/action modes. This client uses browser-only declarative routing, not RSC/actions, but dependencies still require security review and repinning before any production pilot.
